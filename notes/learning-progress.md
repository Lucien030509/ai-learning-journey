# 学习进度与切换规则

最后核对：2026-07-28。

## 进度判断的证据顺序（必须遵守）

在宣布、否定或修改任何学习进度前，按下面顺序同时核对：

1. **之前的教学对话**：Estella 是否已经亲自写、运行、解释或修改过；
2. **Git 提交记录**：相关练习是否已经提交并推送；
3. **当前文件内容和运行结果**：代码是否仍然存在且可运行；
4. **README 文字**：仅作提示，不能单独决定进度。

前面三项中的任何一项与 README 冲突时，不能凭 README 把已完成内容降级为“未完成”。必须先指出冲突、核对其余证据，再更新记录。

这份文件区分两件不同的事：

- **文件已存在**：代码已经在仓库中，且能通过基本运行检查；
- **学习已验证**：Estella 能亲自运行、解释关键部分，并完成一个小改动或回答一个检查问题。

只有“学习已验证”才能把一周标为完成。不能因为文件已经存在、提交过 Git，或程序能运行，就自动进入下一周；同样地，不能因为一次复查时没有重新提问，就否定已经在之前教学中验证过的内容。

## 每周完成门槛

进入下一周前，必须同时满足以下四项：

1. 本周 README 中列出的练习都已经完成；
2. 每个练习用至少一组正常输入成功运行；
3. Estella 能解释本周关键概念，并亲自做过一个小修改；
4. 确认改动后执行 Git 提交并推送，`git status` 没有未提交内容。

## 宣布换周前的必查清单

在从一周切换到下一周前，导师必须逐项确认：

1. 读取本周 README 和全部练习文件；
2. 查看该文件夹的 Git 提交记录；
3. 对照之前对话中 Estella 实际完成的操作；
4. 区分“程序可运行”和“已经教学验证”，但不要求重复已验证练习；
5. 先明确说出“本周已完成”的依据，再开始下一周的第一个小步骤。

没有完成这五项，不宣布换周，也不修改已完成状态。

## 教学时的固定流程

每次只推进一个小步骤：

1. 先说明这一步的目标；
2. 用中文解释一个概念；
3. Estella 自己输入、运行或修改；
4. 检查结果和理解；
5. 只有本周门槛全部满足，才明确宣布“本周完成”并进入下一周。

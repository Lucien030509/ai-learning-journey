# 作品集标准：从 AI 应用工程到研究工程

## 目标

近期作品集要证明：能够把数据和模型变成可靠、可解释、可运行的产品或服务。
长期作品集还要证明：能够像研究工程师一样设计实验、评估改动，并像技术负责人
一样写清技术决策和权衡。

项目数量不是目标。毕业前优先完成 3–4 个高质量项目，而不是许多没有说明、
无法运行的 notebook。

## 必备项目组合

| 项目 | 主要证明的能力 | 最低交付物 |
| --- | --- | --- |
| 数据分析项目 | 数据质量、EDA、可视化、结论沟通 | 可复现分析、图表、结论与限制 |
| 数据和 ML 工程项目 | SQL、数据管线、建模、测试与 API 思维 | 数据库设计、查询、训练评估、测试、README |
| AI 应用项目 | 用户问题、LLM 或 ML 交付、评测、成本与安全 | 可运行 demo 或 API、评测集、失败案例、架构图 |
| 研究工程项目 | 论文理解、复现、基线、实验设计与分析 | 实验配置、结果表、复现说明、对比或消融报告 |

前两个项目服务近期 AI 应用、数据或 ML 工程求职；后两个项目逐步服务研究工程
与技术负责人方向。开始阶段先完成前两个，不跳过基础直接做后两个。

## 每个成熟项目的验收清单

### 问题与数据

- 写清楚目标用户、问题和成功标准。
- 说明数据来源、许可、隐私处理、已知偏差与缺失。
- 不提交密钥、隐私数据或大模型权重。

### 可复现与工程质量

- README 有一条能复制运行的安装与运行命令。
- 固定依赖版本；配置、数据路径和密钥不硬编码。
- 目录分开保存数据、源代码、测试、结果和文档。
- 至少有一个自动检查：单元测试、数据检查或 CI。

### 模型与评测

- 先给出简单基线，再说明新方案为何值得使用。
- 选择与业务问题相符的指标，而不是只展示最好看的数字。
- 展示错误案例、失败模式、局限和下一步。

### AI 系统与研究工程

- 画最小架构图：用户输入、服务、模型或检索、数据和输出。
- 记录延迟、成本、可靠性或安全中的至少一项真实权衡。
- 复现项目要记录代码版本、随机种子、硬件、配置和基线结果。
- 改进实验一次只改变少数因素，并写出假设、对比和结论。

### 技术沟通

- 写一段设计说明：为何选这个方案、替代方案是什么、为何没有选它。
- 能向技术对象讲实现和指标，也能向非技术对象讲价值、风险和限制。

## 当前阶段的最低要求

Python 基础阶段不要求部署、Docker 或论文复现。当前只要做到：

- 代码命名清楚；
- 每个练习能运行；
- README 记录学到了什么；
- 重要练习有一次 Git 提交；
- 能解释自己写的代码和报错。

随着 SQL、Pandas、ML 和 PyTorch 进入路线，上面的标准会逐项加入项目，而不是
一次全部做完。
